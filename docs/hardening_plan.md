# TerraCam Hardening Plan

Tracking document for the architecture review of 2026-07-10. Covers the filter
band indexing error, PTU unresponsiveness diagnosis, sequence engine
hardening, and repository reorganization. Status boxes are updated as work
lands; each phase is implemented and validated before the next begins.

Ground truth (hardware): the filter wheel is two cascaded 10-position wheels
presenting logical positions 0-16. Position 0 is clear (empty slot on both
wheels). The 16 Edmund Optics bandpass filters occupy positions 1-16 in
ascending wavelength order: 400nm at position 1, 50nm steps, with the 975nm
water-vapor filter at position 13, up to 1100nm at position 16.
`config/filter_specifications.json` is the single source of truth for this
mapping.

---

## Findings summary (2026-07-10 review)

### F1. Filter band indexing — persistent +50nm-red error in the analysis layer

The config fix of 2026-05-28 corrected `filter_specifications.json`, but the
old convention survives downstream:

- `scripts/analysis/calibrate_reflectance.py` hardcodes a 15-element
  wavelength list starting at 450nm and assigns wavelengths by sorted band
  index, not by filter position. Result: every band labeled ~50nm too red,
  and the 1100nm filter (position 16) is excluded (`expected = range(1, 16)`).
- `scripts/analysis/generate_derived_products.py` hardcodes the same list in
  `band_index()`; all band-ratio/band-depth products select bands one slot
  bluer than their labels claim.
- `src/fli/io/netcdf.py`: `filter_position` variable `valid_range` is
  [0, 15], excluding position 16; a clear-position capture crashes `add_band`
  (`np.float32(None)`); unknown positions silently get wavelength 0.0; a NaN
  wavelength would corrupt RGB preview band selection (`np.argmin` on NaN).
- `tests/unit/test_netcdf_writer.py`: the filter-config fixture encodes the
  pre-fix convention (position 0 = 400nm, 15 filters, no clear slot, no
  975nm) and its assertions pin it — the test suite has been enforcing the
  wrong mapping.

Data impact: all reflectance cubes and derived products generated by the
analysis scripts carry wrong wavelength labels regardless of capture date,
and lack the 1100nm band. They must be regenerated after the fix. NetCDF
files written by the capture pipeline since 2026-05-28 have correct
wavelength metadata (per-band `wavelength` variable) and do not need
regeneration.

### F2. PTU unresponsiveness — two candidate failure layers

Protocol layer (serial desynchronization; software):
- The discovery probe (`src/ptu/discovery.py`) sends `VM`/`VS`/`V` with one
  `readline()` per command and no echo handling — the E-series PTU echoes
  commands, so the probe leaves the conversation off-by-one-response and the
  controller inherits a dirty buffer.
- `PTUController.send_command()` returns the last unmatched line (garbage)
  after 3 reads instead of raising.
- `await_completion()` timeout leaves stale `A` responses in the buffer; the
  next command mis-reads them. `halt()` does not confirm the halt.
- In the uncommitted `move_to_position()`, `pan_resp.startswith("!")` is dead
  code under `FV` verbose + echo (response begins with the echoed command);
  `_validate_response()` handles this correctly but is not used there.

Power layer (hardware; suspected from the trial):
- Uncommitted config changes (hold/move power LOW/LOW, `sequential_axes`)
  point at peak-current/brownout suspicion. Caution: LOW hold power with the
  camera payload risks tilt-axis sag, which the new post-move position
  verification (tolerance 5 steps) will surface as spurious failures.
- Discriminator: log raw TX/RX bytes with timestamps. Desync shows mismatched
  responses still arriving; brownout shows silence or an unsolicited boot
  banner. Bench test: measure supply voltage at the PTU during a simultaneous
  HIGH-power move.

### F3. Sequence engine fragilities (catalogued 2026-07-10)

- Unchecked FLI C return codes throughout `filter_wheel.py`, `focuser.py`,
  parts of `camera.py` — a failed `FLISetFilterPos` returns silently and the
  mission captures through the wrong filter.
- `camera.wait_for_idle()` swallows all exceptions and returns a bool most
  callers ignore; exposure-wait timeout is a fixed +30s buffer and collapses
  to ~0.45s if `current_exposure_ms` is unset.
- Bare `except: pass` in `device.py close()` and `system._reconnect_devices()`.
- `coordinator.execute_sequence()` error path does not halt the PTU; abort
  paths do not restore a safe state; no per-capture retry policy; no
  checkpoint/resume for long surveys; no mission-level watchdog.
- `tracker.execute_continuous()` has no exception handling around
  compute/point/capture — one transient kills the tracking session.

### F4. Organization

- `auto_expose.py` (mission-critical) lives in `scripts/capture/`; the
  coordinator imports it via path manipulation.
- Device setup boilerplate triplicated across capture scripts.
- 8 loose hardware-diagnostic scripts mixed into `tests/`.
- Config and output paths resolved by filesystem traversal; no env override.
- Stray/untracked files: `IMG_1420.jpeg` (root), `src/fli/io/`,
  `create_mosaic.py`, Edmund PDF spec sheets, pyproject changes.

## Phase 1 — Filter mapping single source of truth (DONE 2026-07-10, pending regeneration)

Rule: `config/filter_specifications.json` is the only place the
position→wavelength mapping exists. Capture-time writers stamp wavelength
into file metadata from the config; analysis reads wavelengths from file
metadata; nothing hardcodes a wavelength list.

- [x] `src/fli/io/netcdf.py`: `valid_range` → [0, 16]; clear position writes
      NaN wavelength/bandwidth (documented in variable attributes); unknown
      filter position raises `ValueError`; RGB preview band selection is
      NaN-safe.
- [x] New `scripts/analysis/band_mapping.py`: loads position→wavelength from
      config; nearest-band lookup with tolerance for analysis products.
- [x] `calibrate_reflectance.py`: wavelengths from config by filter position
      (all 16 filters, positions 1-16); panel/diagnostic band selection by
      wavelength; per-band metadata aligned with cube axis; fails fast on
      unknown/duplicate positions. Also fixed metadata extraction: real
      coordinator captures nest fields under `acquisition_settings`
      (`filter_position`, `exposure_time_ms`), which the old flat-key
      extraction never matched.
- [x] `generate_derived_products.py`: reads band wavelengths from the
      calibration metadata JSON (`--metadata`, default
      `<cube>_metadata.json`); all band selection via nearest-wavelength
      lookup; fails loudly on cubes without metadata; no hardcoded list.
- [x] Tests: fixture rebuilt to the real convention (0 = clear, 1-16 =
      400-1100nm incl. 975); new tests pin position 1 → 400nm, position 13 →
      975nm, position 16 → 1100nm, clear → NaN, unknown position → error.
      113 unit tests pass.
- [x] Validation: full pytest suite green; synthetic 17-position end-to-end
      run through both CLIs (calibration + all 15 derived products);
      real-data check against `out/raw` (loads positions 1-15 as 400-1050nm,
      skips clear, warns on missing position 16 — and the per-band exposure
      profile independently corroborates the mapping: minimum exposure at
      500-600nm at the ICX695 QE peak, ~3s at 1050nm).
- [ ] Regenerate derived products from affected surveys (developer to
      schedule; requires deciding which surveys are still needed).

Open question (developer): is the clear position (0) an intended capture
band in missions? Writer now supports it (NaN wavelength); calibration
continues to skip it.

## Phase 2 — PTU protocol hardening (CODE DONE 2026-07-10, pending hardware trial)

Design decision: echo is kept ENABLED (`EE` at initialize) rather than
disabled. With echo on, every response line begins with the echoed command
("PP1000 *", "PP * Current Pan position is 1000"), giving positive
command/response correlation — send_command() discards any line that does
not correlate, so the protocol self-heals from desync instead of silently
mis-parsing. A second decision: awaits poll PP/TP positions against the
commanded target instead of using the PTU `A` command, because `A` delays
the command interpreter until motion completes (halt would be unresponsive
mid-move) and leaves an unconsumed response if the wait is abandoned.

- [x] Typed exception hierarchy: PTUError / PTUConnectionError /
      PTUCommandError / PTUTimeoutError / PTUProtocolError (exported from
      `ptu`).
- [x] `send_command()` returns the echo-stripped payload or raises; no
      garbage fallback. Prefix-collision stale lines (old "PP1000 *" vs a
      "PP" query) are rejected by requiring the post-echo payload to begin
      with `*`/`!`. Works with echo on or off. This also fixed GPM response
      parsing, which expected `*`-prefixed payloads all along.
- [x] `_resync()` after any timeout: bare-delimiter write to clear a
      partial device-side command, settle, drain input. Buffers also
      cleared on connect.
- [x] `await_completion(pan_target=, tilt_target=)`: position-polled with
      tolerance completion, stall detection (axes frozen off-target →
      early False), and stability fallback when no target is known.
      Position verification is now intrinsic to `move_to_position(wait=True)`.
- [x] `halt()` confirms axes stationary (returns bool), retries once
      through a resync if the command itself fails.
- [x] Discovery probe reads echo-aware correlated replies (VM/VS/V) and
      leaves no unconsumed responses; failures logged at debug.
- [x] Raw TX/RX wire logging on the dedicated `ptu.serial` logger
      (`logging.getLogger("ptu.serial").setLevel(logging.DEBUG)`) for
      field diagnosis of desync-vs-power faults.
- [x] 26 mock-serial unit tests: echo on/off, command errors, stale-line
      discard, prefix collision, timeout+resync, stall, sequential axes,
      halt confirmation, discovery probing. Full suite 139 passing.
- [ ] Hardware validation trial: exercise initialize/move/halt on the real
      D100E with `ptu.serial` debug logging enabled; capture a log during
      a simultaneous move at the configured power modes.
- [ ] Bench: supply voltage measurement during simultaneous HIGH-power move;
      decide hold-power policy vs. payload sag (LOW hold + heavy payload
      may trip the new stall/verification checks).

Hardware-dependent validation items for all phases are tracked in
docs/hardware_checklist.md (living document).

## Phase 3 — Sequence engine contracts (CODE DONE 2026-07-10, pending field drills)

Audit correction discovered during implementation: FLI C return codes were
already checked — `FLILibrary.getDll()` installs `chk_err` as the ctypes
`restype` on every API function, so all calls raise `FLIError` on failure
(finding F3's "unchecked C calls" was overstated). The genuine defects were
in the error paths themselves: `FLIError`/`FLIWarning` required two
constructor arguments while every raise site passed one, so failures
crashed with `TypeError` instead of reporting; `chk_err`'s positive branch
had the same bug.

- [x] lib.py: `FLIError`/`FLIWarning` single-argument construction fixed;
      positive C returns warn instead of crashing. Regression tests added.
- [x] device.py: `DEBUG=False` (was True — every import wrote
      `.FLIDebug.log` into the CWD, the stray file in the repo root);
      `close()` logs failures instead of bare-except, and is safe on
      partially-constructed instances (`__del__` no longer raises).
- [x] camera.py: all DEBUG-gated prints converted to module logging (the
      warnings were invisible in normal operation); `wait_for_idle()`
      logs status-query faults and its timeout; redundant poll-count
      valve removed (the elapsed-time deadline already bounds the loop);
      exposure timeout message includes the last camera status.
- [x] system.py: `wait_for_temperature()` survives transient USB faults
      and abandons after 5 consecutive read failures instead of crashing
      or looping; reconnect/close paths log instead of bare-except.
- [x] Coordinator safe-state: `_enter_safe_state()` halts the PTU with
      confirmation, closes the shutter, and logs the terminal position;
      invoked on unhandled sequence exceptions, watchdog expiry, and
      `abort_sequence()` (Ctrl+C path). Each step is independent and the
      routine never raises.
- [x] Coordinator retry policy: `_capture_at_filter` retries the filter
      move + capture once (the acquisition layer already retries USB
      faults 3x internally); save-path failures are not retried.
- [x] Mission checkpoint/resume: checkpoint JSON written after every
      position, cleared on completion; `execute_sequence(resume=True)`
      skips completed positions; `run_grid_survey.py --resume`.
- [x] Mission watchdog: `SequenceConfig.max_duration_s` /
      `run_grid_survey.py --max-duration-min` aborts to safe state.
- [x] Tracker continuous loop: per-point exception handling with a
      3-consecutive-failure cap.
- [x] Latent geo-pointing crashes fixed: `execute_single_geo_position`
      called `_capture_at_filter` with a wrong keyword and missing
      required arguments (TypeError on first use), and geo methods called
      nonexistent `SessionLogger.info()`/`.error()` (AttributeError).
- [x] 21 new unit tests (core hardening + coordinator); full suite 160
      passing.
- [ ] Field drills: mid-mission abort (Ctrl+C) and checkpoint resume —
      see docs/hardware_checklist.md.

Deferred (noted, not blocking): GPM response-check style cleanup to typed
errors; adaptive temperature polling; NetCDF I/O timeouts.

## Feature — Az/el pointing backplanes (CODE DONE 2026-07-11, calibration pending)

Per-pixel azimuth/elevation in the PTU reference frame for every mosaic
subframe, including the boresight lever arm: the camera entrance pupil is
offset from the pan/tilt axes intersection (on the tilt axis, forward of
the pan axis), producing parallax ~ offset/range at finite scene range.

- [x] `src/fli/geometry.py`: pinhole + gimbal forward model
      (`CameraModel` with f/principal point/roll/k1 — deliberately the
      same parameters the cylindrical mosaic fit produces, so a fitted
      mosaic model calibrates the backplanes; `MountModel` with the
      camera offset vector and angular boresight offsets;
      `pixel_to_azel` with ray-sphere parallax at a configurable scene
      range). Conventions pinned by 22 unit tests: center pixel ≡
      (pan, tilt); tilt cross-coupling (az scale ~ 1/cos el); parallax
      magnitudes verified analytically.
- [x] `config/ptu_specifications.json` `mount_geometry` section: camera
      offset (forward / along-tilt-axis / up, meters — currently zeros,
      to be measured) and boresight angular offsets.
- [x] NetCDF writer: `backplane_azimuth`/`backplane_elevation` variables
      written on finalize — subsampled 16x node grid by default (with
      pixel-index coordinate variables; bilinear interpolation error is
      negligible), `full` or `none` selectable. Uses encoder-derived
      actual angles (now also stored as `actual_pan_degrees` /
      `actual_tilt_degrees` global attributes). Model parameters stamped
      as variable attributes.
- [x] Coordinator + `run_grid_survey.py`: `--backplanes
      {subsampled,full,none}` and `--scene-range-m`.
- [x] `create_mosaic.py`: `--scene-range-m` enables parallax-corrected
      tile placement in all modes (coordinate placement and the
      cylindrical/opencv tile pointing) via a self-contained copy of the
      boresight formula — equivalence with `fli.geometry` is pinned by a
      unit test because analysis scripts do not import the fli package
      (it loads the camera C library on import).
- [ ] Measure the camera offset vector and update `mount_geometry`.
- [ ] Field validation: overlap self-consistency + celestial cross-check
      (see docs/hardware_checklist.md); calibrate boresight angular
      offsets from a mosaic model fit.
